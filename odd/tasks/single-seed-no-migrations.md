# Single Seed Entry Point and Migration Removal

## Objective
Ensure `seedDatabase()` is the only entry point that loads seed data, and remove every file in `migrations/` without transferring migration behavior into the seed.

## Scope and constraints
- The user explicitly authorized deleting all migration files, including index creation, stock repairs, backfills, and backup-verification tools.
- Remove independently executable demo/test seeding entry points and lazy request-triggered fixture seeding while preserving seed data already initialized by `seedDatabase()`.
- Preserve ordinary business routes and backup restore functionality; do not execute any migration, seed, database, provider, production, or remote operation.
- Preserve `.env.local` and other unrelated user files.
- Delivery strategy: ask-on-risk; forecast exceeds 400 authored lines because 25 migration files and their integration/tests must be removed.
